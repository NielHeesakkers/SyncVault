# SyncVault 3.2.0 — Look & Feel + macOS Depth

**Status:** Design approved, ready for implementation plan.
**Brainstorm date:** 2026-05-24.
**Mockups:** [`docs/design/mockups/`](../../design/mockups/README.md).

This spec covers the v3.1.2 → v3.2.0 release: a complete visual overhaul of the
menu bar app and settings window, a dedicated update flow, a first-launch
onboarding wizard, and three new macOS-depth features (conflict resolution,
Finder integration, notifications and widgets).

The server stays at 3.1.x — no protocol changes. This is a client-side release.

## 1. Goals & non-goals

### Goals

- Consistent visual language across menu bar, settings, update window, onboarding.
- Make the daily-use surface (menu bar) feel like a power-user tool, not a hobby project.
- Move the update flow out of a cramped settings row into its own well-designed window.
- Reduce time-to-first-sync for new users to under 2 minutes.
- Fix recurring user pain: sync conflicts currently overwrite or silently rename — give the user control.
- Give Finder users visible feedback (overlay badges, context menu) without leaving Finder.

### Non-goals

- iOS app, iPad app, Linux client, Windows client. (Stay focused on macOS depth this release.)
- End-to-end encryption.
- Real-time collaboration (presence, comments, @mentions).
- Server admin UI changes.
- New sync protocol features.

## 2. Visual language

All UI surfaces (menu bar popover, settings, update window, onboarding) share one design system.

### Type

- **Body / labels:** SF Pro Text, 12.5px – 14px depending on density.
- **Numerical stats and paths:** SF Mono, ui-monospace. Used for: file sizes, transfer rates, percentages, last-sync timestamps, server URLs, file paths, version numbers, git SHAs. Mono ensures numbers align in columns without explicit width math.
- **Section labels:** 10px, uppercase, letter-spacing 0.08em, `#6e6e73`.
- **H1 inside windows:** 17–22px depending on context.

### Color tokens (dark mode primary)

| Token | Hex | Use |
|---|---|---|
| `bg.window` | `#1c1c1e` | Main window background |
| `bg.card` | `#2c2c2e` | Card / row group background |
| `bg.subtle` | `rgba(255,255,255,0.05)` | Chip background, hover row |
| `text.primary` | `#ffffff` | Names, headings |
| `text.secondary` | `#8e8e93` | Labels, captions |
| `text.tertiary` | `#6e6e73` | Section labels |
| `accent.blue` | `#0a84ff` | Primary actions, links |
| `accent.green` | `#30d158` | Success, synced, install button |
| `accent.orange` | `#ff9f0a` | Update available, warnings |
| `accent.red` | `#ff453a` | Errors |
| `accent.purple` | `#5e5ce6` | Server-side state (in conflict UI) |

Light-mode equivalents derive from the same tokens with inverted contrast. SwiftUI's `Color(.windowBackground)` etc. covers most cases.

### Row pattern

Used in: menu bar sync tasks, settings sync tasks, finder badges (conceptually), conflict UI side panels.

```
[chip 24×24]  [name + optional sub]  [mono stat or pill]
```

- **Chip:** soft-fill background `rgba(255,255,255,0.05)`, 6px radius, 24×24.
- **Folder chip:** `📁` glyph.
- **File chip:** `📄` glyph (no file-type sniffing — generic file icon for all files).
- **Cloud chip:** `☁` glyph with a blue tint `rgba(10,132,255,0.12)` background and `#64b5ff` foreground. Used for on-demand tasks only.

The cloud chip is the only one that gets a tint. Everything else is monochrome.

### Pills

Used to surface status compactly on a row.

- Default `#8e8e93` on `rgba(255,255,255,0.05)`.
- `.live` `#30d158` on `rgba(48,209,88,0.12)` — syncing.
- `.cloud` `#64b5ff` on `rgba(10,132,255,0.12)` — on-demand mode.
- `.paused` `#ff9f0a` on `rgba(255,159,10,0.12)` — user-paused.
- Mono font, 10px, padding `3px 7px`, radius 4px.

### Spacing scale

4, 6, 8, 10, 14, 18, 22 px. Section padding is 18–22px, row padding 9–10px vertical, gap inside rows 10px.

## 3. Menu bar redesign

Mockup: [`menu-bar.png`](../../design/mockups/menu-bar.png), [`menu-bar-icon-states.png`](../../design/mockups/menu-bar-icon-states.png).

### Layout

The popover is 340px wide. Top to bottom:

1. **Status header** (border-bottom). 32×32 status dot + title + mono sub-line: `4 tasks · 247G · sync.example.com`. The dot's color and glyph change with state (✓ green idle, ↻ blue spinning when syncing).
2. **Now syncing** section, only visible during active uploads. Each in-flight file gets an active row: chip, name, progress bar fill (green for upload, blue for download), percentage in mono. Up to 3 visible; rest collapsed into "+N more".
3. **Recently changed**. Up to 3 most recent files with chip + name + sub (task name · time) + mono direction stat (`↑ 42M`).
4. **Sync tasks** with header `4 / 4` mono. On-demand tasks pinned at the top with the cloud chip; a subtle hairline divider; folder-sync tasks alphabetically below. Each row shows chip + name + status pill.
5. **Actions**: Pause, Sync Now (⌘R), Open on Server (primary blue), Settings… (⌘,). Sneltoetsen right-aligned in mono.
6. **Footer**: version + uptime (both mono, very subtle).

When an update is available, an extra action row appears above Pause: `Update to vX.Y.Z` (orange). When ready to install: `Quit & Install vX.Y.Z` (green, bold).

### Menu bar icon

Template image (monochrome, system-tinted). Six states, all built from the same base glyph (the current `arrow.triangle.2.circlepath.icloud` stays) with at most one badge in the bottom-right corner. Badge has a 2px window-bg-colored ring to read on any wallpaper.

| State | Glyph | Badge |
|---|---|---|
| Synced (idle) | base | none |
| Syncing | base | blue, pulses 1.4s ease-in-out |
| Paused | `pause.fill` | none |
| Offline / disconnected | base @ 35% opacity | none |
| Error | base | red |
| Update available | base | orange |
| Recently completed (3s) | base | green, fades out |

Badge priority when multiple apply: error > update > syncing > recently-completed.

## 4. Settings window redesign

Mockup: [`settings-general.png`](../../design/mockups/settings-general.png), [`settings-connection.png`](../../design/mockups/settings-connection.png), [`settings-sync-tasks.png`](../../design/mockups/settings-sync-tasks.png), [`settings-changelog-info.png`](../../design/mockups/settings-changelog-info.png).

### Architecture

Sidebar (180px) on the left with 5 tabs, content area on the right. Standard `NavigationSplitView`. Matches macOS Ventura+ System Settings convention.

Tabs (in order): General, Connection, Sync Tasks, Changelog, Info.

Each sidebar item has a small chip on the left (matching the row chip language). Active item gets `rgba(255,255,255,0.08)` background, blue-tinted chip.

### General

Four cards:

- **Startup**: Launch at login (toggle), Hide dock icon (toggle).
- **Notifications**: Banner on sync complete (toggle), Banner on errors (toggle, default on), Sound (toggle, default off).
- **Bandwidth**: Upload limit (slider with mono `MB/s` readout), Concurrent uploads (segmented 1 / 2 / 4 / 8).
- **Updates**: Check Now (button), Automatically check for updates (toggle). When an update is available a separate orange banner card appears below with `v3.x.y available · Show update…` linking to the dedicated window.

Each toggle has a short sub-line explaining what it does.

### Connection

- Three live health cards at the top: Status (with pulsing green/red dot), Latency (mono ms), Server uptime.
- Server card: URL · Signed in as · TLS certificate (with `valid Nd` pill).
- Versions card: Server / Client / Push protocol — each with a `match` or `connected` green pill, `mismatch` orange if applicable.
- This device card: Name, Device ID (with Copy action), Registered date.
- Bottom actions: Reconnect (primary), Test Server.

### Sync Tasks

Configuration only. No live sync indicators — those belong in the menu.

- Header: title + summary line (`4 tasks · 12.2 GB total`) + `+ Add Task` button (primary).
- Each task is a card with:
  - Head row: chip (folder or cloud) · name · `mode-pill` (two-way / backup / on-demand) · enabled toggle.
  - Below: three stat columns — Files, Size, Last sync.
  - Paths shown in mono under the name: `~/local ↔ /server`.
- CloudDrive (or any on-demand task) pinned at top, divider below.

Clicking a card opens an inspector (existing flow) for edit / filter rules / delete.

### Changelog

Each version is a card:

```
3.2.0 · current    May 24, 2026
─────────────────────────────────
• [bullet of what changed]
• …
```

Current version's number is `#30d158`. Tag pills allowed: `major`, `server-only`, `patch`. Mono font for version and date.

### Info

- Hero card: app icon (rounded 14px, gradient) · app name (22px bold) · `Version 3.2.0 (build 320)` mono · `macOS 14.5 · Apple Silicon` mono.
- Build card: Git commit (with Copy), Build date, Sparkle key fingerprint.
- Links row: chips for the user's own server URL (variable, from `cfg.ServerURL`), GitHub, Report issue, Diagnostics… (exports a log bundle).
- Credits: one-line attribution with MIT license link + dependencies (Sparkle, SQLite).

## 5. Update flow redesign

Mockup: [`update-window.png`](../../design/mockups/update-window.png), [`update-flow.png`](../../design/mockups/update-flow.png).

### Trigger rules

| Trigger | Banner in Settings | Update window | Menu bar row |
|---|---|---|---|
| Auto-check finds update | appears | does NOT open | appears |
| User clicks "Check Now" | appears | **opens** | appears |
| User clicks banner / menu row | stays | **opens** | stays |
| "Skip this version" | gone (until v+1) | closes | gone |
| "Remind me later" | stays | closes (re-prompt in 24h) | stays |

Critical: auto-check never opens a popup. Only manual Check Now or explicit clicks open the window. Auto-check should be invisible.

### Dedicated update window

480px wide, fixed window. Three states inside the same window:

**Available state** (entry point):
- Hero: blue gradient icon (↑) + heading `A new version is available` + mono `v3.1.2 → v3.2.0 · 3.0 MB`.
- "What's new" card with changelog bullets (max ~160px height, scrollable).
- Action bar: `Skip this version` (ghost) · `Remind me later` (ghost) · `Install Update` (primary blue).

**Downloading state**:
- Hero: ↓ icon + `Downloading v3.2.0` + mono `1.9 of 3.0 MB · 4.2 MB/s · ~1s left`.
- Progress card: filename + percentage + linear progress bar (blue fill).
- Action bar: `Cancel` (ghost).

**Ready state**:
- Hero: green-cyan gradient icon (✓) + `v3.2.0 is ready to install` + `Download complete · app relaunches automatically`.
- Progress card shows 100% green fill.
- Action bar: `Install on Quit` (ghost) · `Quit & Install` (primary green, bold).

The user clicks Install → window stays open, transitions to Downloading → transitions to Ready → user clicks Quit & Install at their own pace.

## 6. First-launch onboarding

Mockup: [`onboarding.png`](../../design/mockups/onboarding.png).

540×420 modal window. 4 steps, progress dots at the bottom in the action bar (active dot is a wider pill).

### Step 1 — Welcome

Hero icon (the SyncVault app icon, gradient) + `Welcome to SyncVault` + one paragraph: what the app does, what the wizard will ask for, expected time (~2 minutes). Bottom: `Quit` (ghost) · dots · `Get Started`.

### Step 2 — Connect

Three fields stacked: Server URL, Username, Password. Below them a live test indicator that lights up when credentials work: green dot + mono `Connected · server v3.1.2 · 42 ms latency`. The Continue button stays disabled until the test passes. Bottom: `← Back` · dots · `Continue`.

### Step 3 — First task

Two picker rows (Local folder, Server folder) with sensible defaults (`~/Documents`, `/<username>/Documents`). Below: segmented control for Sync Mode (Two-way sync default, Backup only, On-demand). Hint line under the segmented explains the mode in one line. Bottom: `← Back` · dots · `Start Syncing`.

### Step 4 — Done

Green-cyan gradient icon (✓) + `You're all set` + paragraph pointing to the menu bar ("SyncVault zit nu in je menu bar, rechtsboven") and describing the first sync that's already running. Two secondary actions: `Open Settings` · `Show me the menu bar →` (the latter animates the menu bar icon briefly). Bottom: empty · dots · `Done` (primary green).

## 7. Conflict resolution (new feature)

Mockup: [`conflict-resolution.png`](../../design/mockups/conflict-resolution.png).

720×520 window opened from a menu bar row (`3 conflicts · Resolve…`) or a notification.

### Layout

- **Header** (orange-tinted bg): warning icon + `N sync conflicts need attention` + one-line description.
- **Conflict nav strip**: `Conflict 1 of N · <task>` mono + ◀ ▶ pager.
- **Side-by-side compare**:
  - Left: `Your Mac · <device name>`, blue dot.
  - Right: `Server · via <other device>`, purple dot.
  - Each side: file preview card (16:9 aspect, type-aware thumbnail for PSD/image/PDF, file-type chip fallback), filename in mono, mtime + size in mono with the newer side's mtime highlighted green.
- **Action bar**: `Resolve all later` (ghost) — `Skip` (ghost) — `Keep Server` (purple-tinted) — `Keep Both` (neutral) — `Keep Local` (blue-tinted).

### Special cases

- **Deleted locally + modified on server**: left side shows `Deleted on this Mac` placeholder + a `Restore` action.
- **Text files**: extra `View diff` button opens a side-by-side diff viewer (read-only in 3.2.0; 3-way merge later).
- **No preview available** (binary blob): file-type icon + size only.

### Detection

Existing server-side change-rank logic already tracks per-device updates. Client detects conflict when local mtime > known-base AND server change_rank > known-base. Conflicts are queued in a new `ConflictQueue` table in `SyncDatabase.swift`; menu bar shows the count.

## 8. Finder integration (new feature)

Mockup: [`finder-integration.png`](../../design/mockups/finder-integration.png).

Three components:

### 8.1 FinderSync overlay badges

Already partially implemented via FinderSync extension. Polish the badge designs:

| State | Badge |
|---|---|
| Synced | green ✓ |
| Syncing now | blue ↻ |
| On-demand (cloud only) | purple ☁ |
| Locked by someone | orange 🔒 |
| Error | red ! |

18px circle, 2px window-bg ring, bottom-right of the file icon. Single badge max — error wins over everything.

### 8.2 Sidebar section

A dedicated "SyncVault" section in the Finder sidebar (below Locations) listing all sync tasks. Folder tasks get the folder chip, on-demand tasks get the cloud chip with a blue tint. Click = navigate into that folder. Requires registering an `NSFileProviderDomain` per task (we already register one for on-demand; this extends to folder-sync tasks too).

### 8.3 Context menu

Right-click on a file inside a sync task adds a `SyncVault` section to the context menu:

- **Share via SyncVault…** — opens share modal (token, expiration, password).
- **Open on Server** — web UI focused on this file.
- **Show Versions ⌘V** — version history list.
- **Lock for editing** — server-side lock, visible to other users.
- **Free Up Space** — only for on-demand items, evicts local copy.

Plus a `SyncVault Link` entry in the native macOS Share menu (Cmd-click → Share → SyncVault Link). One click creates the link and copies it to the clipboard.

## 9. Notifications + widgets (new feature)

Mockup: pending — to be added to `docs/design/mockups/notifications-widgets.png` (currently lives only in the brainstorm fragments).

### Rich notifications

UNUserNotificationCenter with category-based actions. Body includes a 38×38 thumbnail (PSD/image type-aware, otherwise file chip glyph). Notification types:

| Event | Actions | Default |
|---|---|---|
| File uploaded / completed | Show in Finder · View on Server | off |
| Conflict detected | Later · Resolve… | on |
| Share link opened | View Activity | off |
| Sync error / repeated fail | Retry · View Log | on |
| New device signed in | It's me · Sign out other | on |
| File received from share | Show in Finder | on |
| Storage 90% full | Manage… | on |

User can toggle each in Settings → General → Notifications.

### Widgets (WidgetKit)

Three sizes:

- **Small (160×160)**: status icon + `All synced` heading + mono `4 tasks · 247G` + `last 12s ago`. Tap = open menu bar (deep link).
- **Medium (340×160)**: header with app icon + `Sync tasks` title + `N / N` mono. Body lists tasks like the menu does — chip + name + status pill. On-demand tasks pinned at top. Tap a row = open that folder in Finder.
- **Lock-screen inline (280×56)**: gradient icon + 2-line text (`SyncVault — all synced` + mono `4 tasks · last 12s ago`). No interaction.

## 12. Out of scope (future)

These were touched on in the brainstorm but deliberately left for later releases:

- **Skip patterns UI** — `node_modules` and friends are auto-skipped already; making the rules configurable in Settings → Sync Tasks → task inspector is a v3.2.x addition.
- **Bandwidth schedule** — limit during work hours, full speed at night. v3.2.x.
- **Trash recovery UI** in macOS — currently web-only. v3.2.x.
- **File versioning UI** in macOS — currently web-only. v3.2.x.
- **Spotlight + QuickLook integration** — out of scope, separate spec when prioritised.

## 13. Implementation phases

Suggested order for the implementation plan (writing-plans skill will detail):

1. **Foundation** — design tokens, shared components (`SVChip`, `SVStatusPill`, etc.).
2. **Menu bar redesign** — most user-facing, validate the visual language end-to-end.
3. **Settings window redesign** — sidebar + 5 tabs.
4. **Update window** — extract from settings, three-state window.
5. **Onboarding wizard** — first-launch flow.
6. **Conflict resolution** — queue + detection + window.
7. **Finder integration** — extend FinderSync extension + sidebar registration.
8. **Notifications** — UN center categories + actions.
9. **Widgets** — separate widget extension target.

Phases 1–5 are the actual 3.2.0 release (visual overhaul + update window + onboarding). Phases 6–9 ship as 3.2.x follow-ups, each with its own implementation plan derived from this design spec.

## 14. Open questions

None blocking. Items the implementation plan should explicitly choose:

- Whether to support light mode at parity, or dark-mode-first with a usable light-mode fallback.
- Exact tap targets for the menu bar rows (right now 36px — Apple HIG is 32px minimum).
- Whether widgets get a refresh interval (60s default) or push via the existing SSE stream.
